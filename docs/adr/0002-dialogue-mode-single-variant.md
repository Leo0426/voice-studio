# dialogue-mode-single-variant

Status: accepted

对话模式（一篇脚本多角色发声）MVP 限定一场对话内所有角色使用同一模型变体，脚本采用纯文本行级标记
（「角色名：台词」，括号可携带每段风格指令，如「Vivian（用愤怒的语气）：台词」）。
因为流式边听边合成是本 App 的核心体验（ADR-0001 正是为它选型 MLX Swift），而三种发声方式绑定不同模型变体
（预置=CustomVoice、克隆=Base、设计=VoiceDesign），跨变体要么按段换载（约 3s/次，角色交替时体验崩坏）、
要么多模型常驻（4-6 GB 内存，8/16GB 机型不友好）、要么分组预合成（放弃流式）——三者都伤害核心体验；
单变体内 CustomVoice 9 音色 × 每段独立指令、Base 内多克隆音色，展示力已足够。

## Considered Options

变体边界：
  单变体（选定）: 接口不变、流式保留、内存不变；代价是不能跨变体混搭
  按段换载: 每次约 3s，对话场景角色频繁交替，不可用
  多模型常驻: 一步到位但 4-6 GB 常驻 + 加载管理复杂度，留作高配机型后续增强
  分组预合成: 允许跨变体但放弃边听边合成，仅适合导出优先场景

脚本表示：
  纯文本行级标记（选定）: 稿子在 App 外生产、整篇粘贴是主路径；解析器是 TTSCore 纯函数可 TDD；
    无标记文本 = 现状单音色合成，对话模式是现有流程的超集而非并列分支
  结构化逐行编辑器: 无解析歧义但 UI 工作量大、长稿粘贴不友好；可日后作为标记之上的可视化视图追加
  srt/剧本导入: 格式长尾杂；可日后作为新解析前端产出同一 DialogueScript 模型

## Consequences

- InferenceEngine 契约零改动；新增编排层（DialogueSynthesizer）逐段调用引擎、按序转发 AudioChunk 给现有播放器。
- DialogueScript 解析器落在 TTSCore，纯函数；误判防护规则：行首到冒号 ≤N 字符且为合法角色名才算台词行，
  中英冒号均可，无标记行归属上一段（或旁白）。
- 角色绑定面板在合成前校验：所有角色映射到同一变体的音色，混用即拦截；缺模型复用现有"去下载"提示。
- 行内括号指令覆盖全局 instruction；超长单段交给现有 TextSegmenter 二次分段；取消语义沿现有机制逐段传播。
- 跨变体混搭的演进路径已预留：编排层按段调度，未来只需扩展"段→引擎"路由（多模型常驻增强）。
