# 领域文档

工程类 skills 在探索代码库时，应如何读取此仓库的领域文档。

## 布局：单一上下文

本仓库是单一上下文布局——根目录一个 `CONTEXT.md`，系统级决策在 `docs/adr/`：

```
/
 CONTEXT.md            ← 领域词汇表与核心不变量
 docs/adr/             ← 架构决策记录（0001 起编号）
 docs/generated/       ← skill 产出的 PRD / spike 记录（事实依据，非规范）
 Sources/
```

## 探索前，先读取这些

- 仓库根目录的 **`CONTEXT.md`** — 项目领域语言。
- **`docs/adr/`** — 读取涉及你即将操作区域的 ADR。

如果这些文件不存在，**静默继续**。不要标记它们的缺失；不要主动建议创建。生产类 skill（`decision-forge`、`domain-modeling`）会在术语或决策真正需要时懒加载创建它们。

## 使用词汇表中的术语

当输出命名一个领域概念时（issue 标题、重构提案、假设、测试名称），使用 `CONTEXT.md` 中定义的术语。不要漂移到词汇表明确避免的同义词。

如果你需要的概念不在词汇表里，这是一个信号——要么你在发明项目不使用的语言（重新考虑），要么存在真正的空缺（记录下来，留给 `domain-modeling` 处理）。

## 标记 ADR 冲突

如果你的输出与现有 ADR 相矛盾，明确标注，而不是静默覆盖：

> _与 ADR-0001（MLX Swift 推理运行时）冲突——但值得重新讨论，因为……_
